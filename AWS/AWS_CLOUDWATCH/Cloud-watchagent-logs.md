# Monitor Amazon EC2 Logs using Amazon CloudWatch

## 📌 Project Overview

This project demonstrates how to centrally collect, monitor, and manage Amazon EC2 log files using **Amazon CloudWatch Logs** and the **Amazon CloudWatch Agent**.

Instead of logging into the EC2 instance every time to inspect logs, the CloudWatch Agent continuously collects log files and sends them to Amazon CloudWatch Logs, where they can be searched, monitored, and retained according to business requirements.

# Understanding CloudWatch Logs

CloudWatch Logs stores **text-based log files** generated by:

- Linux Operating System
- Applications
- NGINX
- Apache
- Docker
- Kubernetes
- Custom Applications

Example:

```
Jul 29 06:40:15 systemd Started nginx
Jul 29 06:40:30 sshd Accepted publickey
Jul 29 06:41:01 sudo ubuntu executed apt update
```

# CloudWatch Metrics vs CloudWatch Logs

| CloudWatch Metrics | CloudWatch Logs |
|-------------------|-----------------|
| Numerical Data | Text Data |
| CPU | syslog |
| Memory | auth.log |
| Network | nginx logs |
| Disk | application logs |

# Step 3 — Create CloudWatch Agent Configuration

Create the configuration file.

```bash
sudo vim /opt/aws/amazon-cloudwatch-agent/etc/amazon-cloudwatch-agent.json
```

Paste the following JSON.

```json
{
  "metrics": {
    "namespace": "CWAgent",
    "append_dimensions": {
      "InstanceId": "${aws:InstanceId}"
    },
    "metrics_collected": {
      "mem": {
        "measurement": [
          "mem_used_percent"
        ],
        "metrics_collection_interval": 30
      }
    }
  },
  "logs": {
    "logs_collected": {
      "files": {
        "collect_list": [
          {
            "file_path": "/var/log/syslog",
            "log_group_name": "ec2-system-logs",
            "log_stream_name": "{instance_id}/syslog"
          },
          {
            "file_path": "/var/log/auth.log",
            "log_group_name": "ec2-system-logs",
            "log_stream_name": "{instance_id}/auth"
          }
        ]
      }
    }
  }
}
```

---

# JSON Configuration Explained

## Metrics Section

```
metrics
```

Collects custom CloudWatch Metrics.

---

## append_dimensions

```
"${aws:InstanceId}"
```

Automatically adds EC2 Instance ID to every metric.

Example

```
InstanceId=i-07b675897575c7986
```

---

## metrics_collected

```
mem_used_percent
```

Collects Memory Utilization.

Collection Interval

```
30 seconds
```

---

## Logs Section

```
logs
```

Configures CloudWatch Log Collection.

---

## file_path

```
/var/log/syslog
```

Linux System Logs

Contains:

- System Services
- Cron Jobs
- Package Updates
- Kernel Messages

---

```
/var/log/auth.log
```

Authentication Logs

Contains:

- SSH Login
- Failed Login
- sudo Commands
- Authentication Events

---

## log_group_name

```
ec2-system-logs
```

CloudWatch Log Group.

Think of it as a folder containing multiple log streams.

---

## log_stream_name

```
{instance_id}/syslog
```

Automatically creates separate log streams for every EC2 instance.

Example

```
ec2-system-logs

├── i-07b675897575c7986/syslog
├── i-07b675897575c7986/auth
├── i-0abcd123456/syslog
└── i-0abcd123456/auth
```

# Step 4 — Apply Configuration

```bash
sudo /opt/aws/amazon-cloudwatch-agent/bin/amazon-cloudwatch-agent-ctl \
-a fetch-config \
-m ec2 \
-c file:/opt/aws/amazon-cloudwatch-agent/etc/amazon-cloudwatch-agent.json \
-s
```

This command:

- Reads JSON
- Validates JSON
- Converts JSON into TOML
- Starts CloudWatch Agent

Expected Output

```
Configuration validation succeeded
```

# Best Practices

- Use IAM Roles instead of Access Keys.
- Use dynamic placeholders like `${aws:InstanceId}` and `{instance_id}`.
- Configure log retention to reduce storage costs.
- Create separate Log Groups for different applications.
- Monitor agent health regularly.
- Restrict IAM permissions to the minimum required.

---

# Cost Considerations

CloudWatch Logs charges for:

- Data ingestion
- Log storage
- Log Insights queries

Always configure a retention policy to prevent unnecessary storage costs.

# Interview Questions

### Why do we need CloudWatch Agent?

To collect custom metrics and operating system/application log files that EC2 doesn't publish by default.

---

### What is a Log Group?

A logical container used to organize related log streams.

---

### What is a Log Stream?

A sequence of log events from a single source, such as one EC2 instance or one log file.

---

### What is Log Collection?

The process of continuously reading log files from a server and sending them to CloudWatch Logs.

---

### Why configure a retention policy?

To automatically delete old logs, control storage costs, and comply with data retention requirements.
